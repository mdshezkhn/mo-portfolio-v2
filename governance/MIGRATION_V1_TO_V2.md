# Migration from Procedural Templates to Graph-Driven Pure Renderers (v1 → v2)

## Architectural Rationale
The legacy `v1` pipeline generated professional outputs by merging sparse data with rich JSON templates (`templates/cv/profiles/*`) inside procedural generation scripts (`build_view_models.py`, `render_markdown.py`). This coupled rendering logic with data logic, meaning new roles or variations required writing new procedural code and hardcoded templates.

The `v2` architecture completely decouples data from presentation. It builds a canonical **Graph**, resolves that graph into a semantic **Profile Domain Model**, projects consumer-specific **View Models** (like `cv_vm.json`), and feeds those into **Pure Renderers** (`render_html_cv.py`, `render_md_cv.py`). This ensures:
1. **Canonical Integrity**: All data is grounded in verifiable YAML sources.
2. **Deterministic Output**: The output is purely a function of the input facts, enabling reproducibility.
3. **Decoupled Formatting**: Renderers do not make semantic decisions.

## Removed Components
* `scripts/build_view_models.py` (legacy procedural view generation)
* `scripts/render_markdown.py` (legacy procedural Markdown generation)
* `templates/cv/profiles/*` (legacy JSON template fallbacks)

## Compatibility Guarantees
* **Structural Equivalence**: The pure renderers are guaranteed to produce structurally identical sections, headings, and data ordering as the `v1.3.0` reference baseline.
* **Canonical Text Equivalence**: All verifiable textual claims generated by `v2` exactly match the legacy baseline, differing only by encoding anomalies (e.g. smart quotes/en-dashes vs. hyphens) and whitespace normalization.

## Rollback Strategy
The `v1.3.0` outputs have been frozen in `reference/baselines/v1.3.0/`. Should a catastrophic structural defect be identified in `v2.0.0-rc1` that blocks a release, the frozen legacy HTML and Markdown outputs can be manually deployed to `compiled_assets/` while remediation occurs.

## Validation Evidence
We have automated canonicalization tests (`tests/reference/test_html_regression.py` and `test_markdown_regression.py`) that run on every CI build. These explicitly parse and canonicalize both the newly generated `cv_v2` outputs and the frozen `v1.3.0` reference artifacts, asserting byte-for-byte identity on the canonicalized strings.

## Release Acceptance Criteria
Promotion from `v2.0.0-rc1` to `v2.0.0` requires a defined acceptance period satisfying the following:
* ✓ All contract tests passing
* ✓ All schema validations passing
* ✓ All semantic validations passing
* ✓ Reference regression tests passing
* ✓ Clean build from fresh checkout
* ✓ Successful deployment
* ✓ Manual browser verification
* ✓ No release-blocking defects during evaluation period
