### Constitution Amendment Rules
No implementation or contributor may silently modify constitutional rules. Any modifications to this specification require:
1. **Justification:** Clear reason explaining why the change is necessary.
2. **Impact Assessment:** Evaluation of how the change affects recruiter usability and cognitive load.
3. **Evidence Review:** Ensuring any new claims align with `CANONICAL_PROFILE.md` and have corresponding Level A or B evidence.
4. **Recruiter Impact Review:** Confirming that the change does not dilute or contradict the core 60-second value proposition.
5. **Version Control:** Mandatory version increment and detailed log entry in Section 15.

### Stability Categories
To facilitate long-term maintenance, sections of this portfolio are categorized by expected stability:
* **Immutable:** Mission, Evidence Standards, Document Authority, Trust Architecture, Recruiter Journey, and Decision Frameworks. (Altered only via formal constitutional amendment).
* **Controlled:** Colors, Typography, Navigation layout, CSS structure, Performance budgets, and Cognitive Load limits. (Altered via design-system refinement with structural verification).
* **Dynamic:** Professional Snapshot, Evidence-Based Highlights, Career Timeline roles, Credentials list, and the Evidence Register links. (Regularly updated as new experiences and verifications occur, conforming to layout rules).

## 8. Recruiter Cognitive Load Rules

To prevent cognitive fatigue and ensure rapid information retrieval, the interface must comply with these metrics:
* **Maximum paragraph length:** 4 lines of rendered text (approx. 50 words).
* **Maximum bullet points per list:** 6 bullets.
* **Maximum clicks to access primary evidence:** 2 clicks from any viewport.
* **Maximum clicks to initiate contact:** 1 click.
* **Maximum scroll before encountering a CTA:** 1 viewport.
* **Text‑to‑Evidence Ratio:** Every metric or performance claim must be accompanied by an inline evidence link (e.g. `[E-2001]`).
* **Visual Calm:** No decorative animations that delay page rendering or content display. No parallax scrolling, auto-playing media, or animated counters.

## 10. Evidence Confidence Levels & Traceability

### Evidence Confidence Scale
All claims must be classified and visually distinguished according to this confidence scale:

| Level | Definition | Visual Indicator / Class |
|---|---|---|
| **Level A** | Independently verifiable primary documentation issued by a third party (e.g., degree certificates, transcripts, official employment verification letters). | Badge: `Verified Document` (Green) |
| **Level B** | Contemporaneous documentary evidence issued by a third party (e.g., lesson observations, internal feedback forms, PGCE essays graded by university). | Badge: `Institutional Record` (Blue) |
| **Level C** | Self-reported professional claims backed by internal narratives but lacking independent verification documents. | Badge: `Self-Reported` (Amber) |
| **Level D** | Aspirational statements, target roles, or professional goals. | Badge: `Future Target` (Grey) |

### Traceability Pipeline
Every factual claim displayed on the portfolio must map through the following pipeline:
$$\text{Public Claim Wording} \rightarrow \text{Claim ID (CLAIM\_REGISTER.md)} \rightarrow \text{Evidence ID (Evidence Matrix)} \rightarrow \text{Verification Status (A/B/C/D)} \rightarrow \text{Display Location}$$

## 11. Design & Typography Guidelines

### Color Palette
The color scheme must represent a premium, professional educational brand. Accent colors are restricted to maintain visual consistency:
* **Primary Color (Base):** Dark Violet (`#4C3A6B`) - communicates academic depth, authority, and professionalism.
* **Secondary Color:** Light Navy (`#2C3E6B`) - provides harmonious support for borders, secondary titles, and links.
* **Neutral Backgrounds:** Sleek dark mode (`#121016` to `#1A1822`) or off-white/light gray (`#F9F9FB`) for high contrast readability.
* **Status Colors:** Restricted to Emerald Green (Verified/Success), Steel Blue (Institutional), Amber (Pending/Review), and Charcoal Gray (Aspirational).

### Typography
To maintain consistent cross-platform rendering and avoid blocking page loads, the site must use system fonts:
* **Body and Headings:** `Inter, -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial, sans-serif`
* **Size Hierarchy:** Headings must scale proportionally using standard rems (e.g., `h1` = 2.5rem, `h2` = 1.75rem, `body` = 1rem, `caption` = 0.85rem).
* **Line Height:** Minimum 1.5 for body text to ensure optimal scanning on mobile screens.

## 13. Portfolio Anti-Patterns
The following practices are strictly forbidden. Any code reviews containing these patterns must be rejected automatically:
* **Inflated metrics:** Claiming team or student numbers that lack Level A/B evidence.
* **Generic inspirational quotes:** Using placeholders or cliché educational slogans.
* **Skill progress bars:** Visual percentages or meters representing skills (e.g., "EAL: 90%").
* **Animated counters:** Text numbers that count up upon scrolling.
* **Endless scroll or scroll-jacking:** Breaking default browser scrolling behaviors.
* **Stock photos:** Decorative classroom stock images. Use real, authorized media or clean, structured geometric patterns.
* **Walls of text:** Paragraphs exceeding 4 lines without lists, bold keywords, or tables.
* **Auto-playing media:** Audios or videos playing automatically.
* **Accents excess:** Using more than 2 distinct colors for branding.
* **Hidden navigation:** Mobile hamburger menus on desktop displays.
* **Decorative animations:** Animations that do not serve to deliver information or establish spatial relationships.

## 16. Technical Performance Budgets

The portfolio implementation must satisfy these strict budgets. Any build that degrades performance below these metrics is blocked from release:
* **Largest Contentful Paint (LCP):** $< 2.5\text{ seconds}$ on standard mobile connections.
* **Interaction to Next Paint (INP):** $< 200\text{ milliseconds}$.
* **Cumulative Layout Shift (CLS):** $< 0.1$.
* **JavaScript Budget:** Maximum 50KB total bundle size (no external heavy frameworks unless strictly required and justified).
* **CSS Budget:** Unified, clean CSS files under 20KB.
* **Image Assets:** All images optimized in WebP format; maximum size 150KB per asset.
* **Lighthouse Scores:**
  - Performance: $\ge 95$
  - Accessibility: $\ge 95$ (WCAG AA minimum)
  - Best Practices: $\ge 95$
  - SEO: $\ge 95$
